This assignment used OpenAI Codex to extend an existing Smart Campus prototype rather than rebuild it from an empty project. The context supplied to the assistant included the repository map, the original acceptance criteria, the new capacity and equipment requirements, the fixed demonstration clock, and the restrictions against databases, authentication, and real booking data.

Useful suggestions included separating filtering from availability validation, retaining the original regression tests, and passing the chosen room's bookings through a small adapter. A proposed state design was modified before implementation: storing a complete availability result would risk showing stale feedback after a room change. The implementation instead derives feedback from the selected visible room once a check has been requested. Adding several policy classes was also unnecessary for this small application.

Verification was performed by the assistant using executable tests, TypeScript, ESLint, a production build, before-and-after decision comparisons, and real browser interactions. These checks independently exercised generated code against explicit expected outcomes. The student has not independently repeated these checks, so this reflection does not claim personal verification that did not occur. All test results and screenshots are preserved for inspection.

Boundary tests reinforced the distinction between exactly 120 and 121 minutes, and between touching and overlapping intervals. Mounted interface tests also required room selection, filtering, schedules, and feedback to remain synchronized. Next improvements would include explicit campus timezone handling, a visible reason when automatic fallback selection occurs, and accessibility testing with assistive technology. These improvements should preserve the current read-only demonstration scope.
